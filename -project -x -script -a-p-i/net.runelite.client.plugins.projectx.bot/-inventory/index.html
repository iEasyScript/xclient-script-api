Inventory

public class Inventory

The player's backpack: a cached view of the 28 inventory slots plus the actions scripts run on them (interact, use, drop, combine, wield, sell, move).

The view is a list of Items in ascending slot order. It is replaced as a whole whenever the inventory container changes and is never edited in place, so a reader always sees one consistent snapshot and waitForInventoryChanges can spot a change by reference.

Lookups never throw for a missing item; they answer null, -1, 0, false or an empty list. Actions answer true once a click was attempted, which says nothing about whether the game accepted it. Every wait goes through Global, so on the client thread waits fail fast and pauses are skipped.

Name lookups come in three flavours, and the default differs per member (see each one): exact (equal ignoring case), partial (contains, ignoring case) and partial-shortest (partial, and among several hits the shortest name, then the lowest slot).
