ScriptReliability

public final class ScriptReliability

Script reliability and recovery: helps a script notice when it is failing or stuck and either get back on track or stop cleanly, instead of hanging, looping forever or carrying on in a broken state. It only observes, checks, retries and stops; it never changes how the script plays.

Using it from a script

Every Script has one, from reliability(). Nothing changes for a script that never calls it.
  1. Wrap actions that can fail in a guarded step: preconditions, the action, how to confirm it worked. A failed attempt is retried with a growing wait, up to the player's "Retries per action".
  2. Give a recovery handler for when a step still fails: walk back to the last checkpoint, re-bank, close an interface.
  3. Call tick once per loop, after super.run(), so a loop that runs but gets nowhere is noticed. Mark real progress with checkpoint, or give a progress signal.
  4. When a result says isScriptStopping, return from the loop.

public boolean run(MyConfig config) {
    reliability()
        .trackProgress(() -> Inventory.count("Logs"))
        .onRecover(ctx -> {
            Checkpoint cp = ctx.getCheckpoint();
            return cp != null && cp.getLocation() != null && Walker.walkTo(cp.getLocation());
        });

    mainScheduledFuture = scheduledExecutorService.scheduleWithFixedDelay(() -> {
        if (!ProjectX.isLoggedIn() || !super.run() || !reliability().tick()) return;

        if (Inventory.isFull()) {
            ActionResult open = reliability().step("Open bank")
                .action(Bank::openBank)
                .verify(Bank::isOpen, 5_000)
                .run();
            if (!open.isSuccess()) return; // retried, recovered or stopped already

            ActionResult deposit = reliability().step("Deposit logs")
                .require(Preconditions.bankOpen())
                .action(() -> Bank.depositAll("Logs"))
                .verify(() -> !Inventory.hasItem("Logs"), 3_000)
                .run();
            if (deposit.isSuccess()) reliability().checkpointAtPlayer("Banked");
        }
    }, 0, 600, TimeUnit.MILLISECONDS);
    return true;
}

Escalation

A failed attempt is retried. A step that still fails is counted, logged, and handed to the recovery handler. When the player's "Failures before stopping" is reached (failed steps in a row, or the same step failing that many times without once succeeding, which catches a loop that alternates between a working and a broken step), or a step is UNRECOVERABLE, the script is stopped safely: the player gets a message saying why and the reason is logged. No progress for the player's "No-progress timeout" calls the recovery handler once, and stops the script if a second timeout passes without progress (straight away when there is no handler).

Progress

Without a progress signal, a successful step or a checkpoint counts as progress. With one, only a change in the signal or a checkpoint does, so a script that "succeeds" at opening and closing the bank forever is still caught. Time spent logged out, paused, on a break, or anywhere the loop did not tick for more than {@value #PAUSE_GAP_MS} ms is not counted.

Threads

Steps, ticks and recovery run on the calling script thread. Guarded steps refuse to run on the client thread, because they wait between attempts. All state is safe to read from any thread.

With "Enable script reliability" off, steps still run, once, and still return their result, but nothing is retried, recovered, or stopped automatically.
